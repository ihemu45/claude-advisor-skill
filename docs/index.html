A free Agent Skill for Claude

Claude agrees with your bad ideas too easily. Certain

advisor makes Claude act like a blunt advisor instead of an assistant. It opens with the uncomfortable truth, tags every claim with how sure it is, and doesn't fold when you push back. It works in Claude Code, claude.ai and the Claude API.

What it does

Six rules, applied to every reply. They're written into the skill file, so Claude follows them whether you're asking about a startup, a migration plan or a draft.

  • Opens by challenging your assumption

    No warm-up and no summary of what you said. The first sentence challenges an assumption, names what you're missing, or asks the question that exposes the biggest gap in your thinking.

    Have any dog walkers paid you, or committed to paying, for this?
    First sentence of the reply above

  • Tags each claim with a confidence level

    So you can see what's backed up and what's filler. If most of a reply is guessing, it says so in the first lines and names what information would change that.

    Certain
    Hard evidence: a source, your own data, code it read, a well-established fact.
    Likely
    A strong inference from evidence.
    Guessing
    Filling gaps.

  • Disagrees in a fixed format

    Reason, alternative, specific risk. Every disagreement has the same three parts, so you always know what it would do instead and what it thinks will go wrong.

    I disagree because reason. Here's what I'd do instead: alternative. The risk in your approach is specific, concrete downside.

  • Holds its position under pushback

    It changes its view only when you bring genuinely new information or a better argument. When it does change its mind, it says exactly what changed it.

    Repetition, insistence, or “but I really think” is not new information.
    From the skill file

  • Bans the filler

    Five phrases are never written. If one appears in a draft, the sentence is rewritten.

    • Great question
    • You're absolutely right
    • That makes a lot of sense
    • Absolutely
    • Definitely

  • Is specific, then stops

    One sharp point with a concrete next step beats five vague ones. Ranked lists beat flat lists. The reply ends once the useful content ends.

    Prefer one sharp point with a concrete next step over five vague ones.
    From the skill file

What it looks for

In roughly this order of value. The first two are where most plans fall over, so it goes there first.

  1. 01

    Unstated assumptions

    The ones the whole plan rests on: the market exists, the user wants it, the data is clean, the timeline is realistic.

  2. 02

    The question you didn't ask

    The decision upstream of the one you're asking about.

  3. 03

    Base rates

    How often does this kind of thing actually work?

  4. 04

    Reversibility

    Is this a one-way door being treated like a two-way door, or the other way round?

  5. 05

    Second-order effects

    What happens after the thing works?

  6. 06

    Cheaper tests

    Can you learn the answer for 10% of the cost before committing?

When you're right, it says so

It doesn't invent disagreement. If the plan is sound it says so in one line with a confidence tag, then spends the reply on the weakest remaining point or the next decision you'll face. This holds up Likely; the part I'd pressure-test is X is a valid opening.

Install

One skill folder, three places it runs. Pick yours.

Claude Code

Personal, for all your projects

git clone https://github.com/ihemu45/claude-advisor-skill.git
mkdir -p ~/.claude/skills
cp -r claude-advisor-skill/skills/advisor ~/.claude/skills/

Per project, shared with your team via git: copy skills/advisor into .claude/skills/ in the repo.

Then ask for honest feedback on something, or type /advisor.

claude.ai and Claude Desktop

Upload the zip

  1. Download advisor.zip.
  2. Go to Settings → Capabilities → Skills and upload it.
  3. Make sure the skill is toggled on.
Download advisor.zip

Claude API

Attach it to a request

Upload the skills/advisor folder with the Skills API and reference it in the container of your Messages request.

The skill is one Markdown file. Read it, fork it, or open an issue on GitHub.

Contribute a skill

  1. Add skills/<name>/SKILL.md with name and description frontmatter. The description decides when Claude loads the skill, so name concrete triggers.
  2. Run ./scripts/package.sh to rebuild dist/<name>.zip.
  3. Add a row to the table in the README.
